# WebSocket Protocol v3.0

Protocol specification for MConnect V2 real-time communication.

## Overview

Protocol v3.0 extends v2.0 with:
- MCP (Model Context Protocol) message routing
- OAuth JWT authentication (token in first message, not URL parameter)
- Structured error responses with retry hints
- Binary message support for large outputs
- Push notification device token registration

**Connection URL:** `wss://{host}/ws`

**Max payload:** 1 MB

**Idle timeout:** 120 seconds

## Message Format

All messages are JSON-encoded. Every message includes a `type` field as the discriminator.

```typescript
interface BaseMessage {
  type: string;       // Message type discriminator
  id?: string;        // Optional ID for request/response correlation
  timestamp?: number; // Unix timestamp (server messages always include this)
}
```

## Connection Lifecycle

```
Client                                    Server
  |                                         |
  |--- WebSocket connect to /ws ----------->|
  |                                         |
  |--- auth { token, clientType } --------->|  (must send within 10s)
  |<-- auth_success { clientId, userId } ---|
  |<-- session_list { sessions } -----------|
  |                                         |
  |--- session_attach { sessionId } ------->|
  |<-- session_state { state } -------------|
  |<-- agent_list { agents } ---------------|
  |<-- control_status { state } ------------|
  |                                         |
  |--- terminal_input { agentId, data } --->|
  |<-- terminal_output { agentId, data } ---|
  |                                         |
  |<-- heartbeat (every 30s) ---------------|
  |--- heartbeat_ack { timestamp } -------->|
  |                                         |
  |--- session_detach -------------------->|
  |                                         |
```

### Authentication

The first message after connection **must** be an `auth` message. If not received within 10 seconds, the server disconnects the client.

### Heartbeat

The server sends a `heartbeat` message every 30 seconds. Clients must respond with `heartbeat_ack`. Clients that don't respond within 90 seconds are disconnected.

### Input Arbitration

MConnect uses a priority-based input arbitration system:

1. **PC clients** have priority when actively typing (within a configurable idle window)
2. **Mobile clients** can request **exclusive control** (5-minute timeout)
3. Input from lower-priority clients is rejected with an `input_rejected` message
4. Rate limiting applies: 100 characters/second per client

## Client -> Server Messages

### `auth`

Authenticate with the server. Must be the first message sent.

```json
{
  "type": "auth",
  "token": "<JWT access token>",
  "protocolVersion": "3.0",
  "clientType": "mobile"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `token` | string | Yes | JWT access token |
| `protocolVersion` | string | Yes | Must be `"3.0"` |
| `clientType` | string | Yes | `"pc"` or `"mobile"` |

### `session_attach`

Join a session to receive real-time updates and send input.

```json
{
  "type": "session_attach",
  "sessionId": "uuid"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `sessionId` | string (UUID) | Yes | Session to join |

### `session_detach`

Leave the current session.

```json
{
  "type": "session_detach"
}
```

### `terminal_input`

Send input to a specific agent's terminal.

```json
{
  "type": "terminal_input",
  "agentId": "uuid",
  "data": "ls -la\n"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `agentId` | string (UUID) | Yes | Target agent |
| `data` | string | Yes | Input data (including newlines for enter) |

Subject to input arbitration and guardrail filtering.

### `resize`

Resize the terminal for a specific agent.

```json
{
  "type": "resize",
  "agentId": "uuid",
  "cols": 120,
  "rows": 40
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `agentId` | string (UUID) | Yes | Target agent |
| `cols` | integer | Yes | Column count |
| `rows` | integer | Yes | Row count |

### `control_request`

Request or release exclusive input control.

```json
{
  "type": "control_request",
  "action": "exclusive"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `action` | string | Yes | `"exclusive"` or `"release"` |

Rate limited to 1 request per 10-second window.

### `scrollback_request`

Request terminal scrollback history.

```json
{
  "type": "scrollback_request",
  "sessionId": "uuid",
  "fromLine": 0,
  "count": 100
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `sessionId` | string (UUID) | Yes | Session ID |
| `fromLine` | integer | Yes | Starting line number |
| `count` | integer | Yes | Number of lines to fetch |

Rate limited to 10 requests per second.

### `mcp_forward`

Forward an MCP message to a specific agent.

```json
{
  "type": "mcp_forward",
  "agentId": "uuid",
  "message": {
    "jsonrpc": "2.0",
    "method": "tools/call",
    "params": { "name": "read_file", "arguments": { "path": "/tmp/test" } },
    "id": 1
  }
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `agentId` | string (UUID) | Yes | Target agent |
| `message` | MCPMessage | Yes | MCP JSON-RPC message |

Rate limited to 20 messages per second.

### `heartbeat_ack`

Acknowledge a server heartbeat.

```json
{
  "type": "heartbeat_ack",
  "timestamp": 1706745600000
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `timestamp` | number | Yes | Timestamp from the heartbeat message |

### `ping`

Ping the server for latency measurement.

```json
{
  "type": "ping"
}
```

### `device_token_register`

Register an APNs device token for push notifications via WebSocket.

```json
{
  "type": "device_token_register",
  "deviceToken": "a1b2c3d4e5...",
  "platform": "ios"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `deviceToken` | string | Yes | APNs device token (hex string) |
| `platform` | string | Yes | `"ios"`, `"android"`, or `"web"` |

## Server -> Client Messages

### `auth_success`

Authentication was successful.

```json
{
  "type": "auth_success",
  "clientId": "uuid",
  "protocolVersion": "3.0",
  "clientType": "mobile",
  "userId": "uuid",
  "timestamp": 1706745600000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `clientId` | string | Assigned client ID |
| `protocolVersion` | string | Confirmed protocol version |
| `clientType` | string | Confirmed client type |
| `userId` | string (UUID) | Authenticated user ID |

### `auth_failed`

Authentication failed.

```json
{
  "type": "auth_failed",
  "reason": "expired_token",
  "retryable": true,
  "timestamp": 1706745600000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `reason` | string | `"invalid_token"`, `"expired_token"`, or `"missing_token"` |
| `retryable` | boolean | Whether the client should retry (e.g., after token refresh) |

### `session_list`

List of available sessions (sent after successful auth).

```json
{
  "type": "session_list",
  "sessions": [
    {
      "id": "uuid",
      "state": "running",
      "preset": "claude-code",
      "agentCount": 1,
      "createdAt": "2026-02-05T12:00:00Z"
    }
  ],
  "timestamp": 1706745600000
}
```

### `session_state`

Session state change notification.

```json
{
  "type": "session_state",
  "sessionId": "uuid",
  "state": "running",
  "lastActivity": 1706745600000,
  "timestamp": 1706745600000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `sessionId` | string (UUID) | Session ID |
| `state` | string | `"running"`, `"paused"`, or `"completed"` |
| `lastActivity` | number | Last activity Unix timestamp |

### `terminal_output`

Terminal output from an agent.

```json
{
  "type": "terminal_output",
  "agentId": "uuid",
  "data": "total 42\ndrwxr-xr-x ...\n",
  "timestamp": 1706745600000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `agentId` | string (UUID) | Source agent |
| `data` | string | Terminal output data |

### `agent_status`

Agent status change.

```json
{
  "type": "agent_status",
  "agentId": "uuid",
  "status": "running",
  "timestamp": 1706745600000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `agentId` | string (UUID) | Agent ID |
| `status` | string | `"starting"`, `"running"`, `"idle"`, `"waiting"`, `"exited"`, or `"error"` |

### `agent_list`

List of agents in the current session (sent after `session_attach`).

```json
{
  "type": "agent_list",
  "agents": [
    {
      "id": "uuid",
      "type": "claude",
      "name": "Claude Code",
      "status": "running"
    }
  ],
  "timestamp": 1706745600000
}
```

### `control_status`

Input control state for the session.

```json
{
  "type": "control_status",
  "sessionId": "uuid",
  "state": "pc_idle",
  "activeClient": "uuid",
  "exclusiveExpires": 1706745900000,
  "lastPcActivity": 1706745590000,
  "timestamp": 1706745600000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `sessionId` | string (UUID) | Session ID |
| `state` | string | `"pc_active"`, `"pc_idle"`, `"pc_disconnected"`, or `"mobile_exclusive"` |
| `activeClient` | string? | Currently active client ID |
| `exclusiveExpires` | number? | Unix timestamp when exclusive control expires |
| `lastPcActivity` | number? | Last PC input Unix timestamp |

### `control_response`

Response to a `control_request`.

```json
{
  "type": "control_response",
  "granted": true,
  "expiresAt": 1706745900000,
  "timestamp": 1706745600000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `granted` | boolean | Whether control was granted |
| `reason` | string? | Reason if denied |
| `expiresAt` | number? | Expiration Unix timestamp if granted |

### `input_rejected`

Input was rejected by the server.

```json
{
  "type": "input_rejected",
  "reason": "guardrail_blocked",
  "command": "rm -rf /",
  "timestamp": 1706745600000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `reason` | string | See [Input Rejection Reasons](#input-rejection-reasons) |
| `command` | string? | Rejected command (if guardrail blocked) |

### `scrollback_response`

Terminal scrollback history.

```json
{
  "type": "scrollback_response",
  "sessionId": "uuid",
  "lines": ["$ ls", "file1.txt  file2.txt"],
  "fromLine": 0,
  "totalLines": 500,
  "timestamp": 1706745600000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `sessionId` | string (UUID) | Session ID |
| `lines` | string[] | Scrollback lines |
| `fromLine` | integer | Starting line number |
| `totalLines` | integer | Total lines in buffer |

### `mcp_response`

MCP response from an agent.

```json
{
  "type": "mcp_response",
  "agentId": "uuid",
  "message": {
    "jsonrpc": "2.0",
    "result": { "content": [{ "type": "text", "text": "file contents..." }] },
    "id": 1
  },
  "timestamp": 1706745600000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `agentId` | string (UUID) | Source agent |
| `message` | MCPMessage | MCP JSON-RPC response |

### `client_joined`

A new client connected to the session.

```json
{
  "type": "client_joined",
  "client": {
    "id": "uuid",
    "clientType": "mobile",
    "priority": "normal"
  },
  "timestamp": 1706745600000
}
```

### `client_left`

A client disconnected from the session.

```json
{
  "type": "client_left",
  "clientId": "uuid",
  "timestamp": 1706745600000
}
```

### `heartbeat`

Server keepalive (sent every 30 seconds).

```json
{
  "type": "heartbeat",
  "timestamp": 1706745600000,
  "serverTime": 1706745600000
}
```

Client must respond with `heartbeat_ack`.

### `pong`

Response to a client `ping`.

```json
{
  "type": "pong",
  "timestamp": 1706745600000
}
```

### `error`

Protocol error.

```json
{
  "type": "error",
  "message": "Session not found",
  "code": "SESSION_NOT_FOUND",
  "retryable": false,
  "retryAfterMs": 5000,
  "timestamp": 1706745600000
}
```

| Field | Type | Description |
|-------|------|-------------|
| `message` | string | Human-readable error description |
| `code` | string | See [Error Codes](#error-codes) |
| `retryable` | boolean | Whether the client should retry |
| `retryAfterMs` | number? | Suggested retry delay in milliseconds |

## Error Codes

| Code | Description | Retryable |
|------|-------------|-----------|
| `AUTH_FAILED` | Authentication failed | Yes (after re-auth) |
| `AUTH_EXPIRED` | Token expired | Yes (after refresh) |
| `SESSION_NOT_FOUND` | Session does not exist | No |
| `SESSION_COMPLETED` | Session is already completed | No |
| `NOT_ATTACHED` | Client is not attached to a session | No |
| `RATE_LIMITED` | Rate limit exceeded | Yes (after delay) |
| `GUARDRAIL_BLOCKED` | Command blocked by guardrails | No |
| `INTERNAL_ERROR` | Server internal error | Yes |

## Input Rejection Reasons

| Reason | Description |
|--------|-------------|
| `pc_typing` | PC client is actively typing (mobile input deferred) |
| `other_exclusive` | Another client has exclusive control |
| `rate_limited` | Client exceeded input rate limit (100 chars/sec) |
| `read_only` | Client is in observer mode |
| `guardrail_blocked` | Command blocked by guardrail rules |

## Rate Limits

| Resource | Limit |
|----------|-------|
| Terminal input | 100 characters/second |
| Control requests | 1 per 10 seconds |
| Scrollback requests | 10 per second |
| MCP messages | 20 per second |
| Reconnection attempts | 5 per minute |

## Push Notification Payloads

When the client has registered a device token, the server sends push notifications for important events (delivered via APNs when the client is not connected).

| Type | When |
|------|------|
| `agent_completed` | An agent finishes execution |
| `agent_error` | An agent encounters an error |
| `approval_required` | A command needs user approval (guardrails) |
| `session_idle` | Session has been idle for extended period |

```json
{
  "type": "agent_completed",
  "title": "Agent Completed",
  "body": "Claude Code finished successfully",
  "sessionId": "uuid",
  "agentId": "uuid",
  "agentName": "Claude Code",
  "badge": 1,
  "sound": "default"
}
```
